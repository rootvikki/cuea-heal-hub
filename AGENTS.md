# Project rules

- M-Pesa settings are resolved only in `supabase/functions/_shared/mpesa.ts` (Settings page values override project secrets; Buy Goods uses separate till and store numbers) — one place so STK push, status checks and callbacks never disagree.
- An M-Pesa payment is recorded on the invoice only through `finalizeMpesaSuccess` (conditional update from `pending`/`failed` to `completed`, links a hand-entered code instead of inserting twice) — the callback and the status check can both fire, and this guarantees one payment row. Status-check answers like "still processing" (`isStillProcessing`) are never failures; client waiting lives in `src/lib/mpesaWait.ts`.
- Payment receipts are built per invoice in `src/lib/receipt.ts` from completed payment rows — one receipt layout for Billing, the payment panel and the patient portal.
- Payments-report filtering, grouping and Nairobi-time date ranges live in `src/lib/paymentsQuery.ts` with bun tests beside it (`bun test ./src/lib/paymentsQuery.test.ts`); exports in `paymentsExport.ts` / `paymentsPdf.ts` — keeps report rules testable without the UI.
- Excel exports write totals as live formulas over the detail sheet and dates as Excel serial numbers — users re-filter in Excel, and JS Date conversion drifts by seconds.
- Every printout uses `src/lib/letterhead.ts`: `drawInfirmaryLetterhead` for jsPDF, `printWithLetterhead` for HTML print windows, `openPdfWindow` to open PDFs (tab opened before the async build so pop-up blockers allow it) — single source for the header.
- Test files (`*.test.ts`) are excluded from `tsconfig.app.json` because they use bun's test types.
- A station that serves a ticket with nothing to work on (e.g. Pharmacy with no prescription) must show the patient with an action to add the order or send them on — never fall back to the list, which looks like the patient vanished.
- Payment-mode rules (which modes each patient type may use, the check-in default, which billing methods each mode offers, two-tier pricing) live only in `src/lib/pricing.ts` with bun tests beside it (`bun test ./src/lib/pricing.test.ts`) — registration, check-in, edit biodata and the payment panel all read them, so they can't drift apart.
- Profile gender is normalised to "Male"/"Female" by a database trigger; reports show a missing gender as "Not recorded" — so gaps stay visible instead of looking blank.
- A visit's payment mode lives on `tickets.payment_mode`, set at check-in, and every station and Billing reads it from there. Later changes go through `setVisitPaymentMode` in `src/lib/billing.ts` (the edit-patient form applies it to open visits) — so reception's choice carries through to payment.
- `EditBiodataDialog` reloads the full patient and profile rows before editing — callers pass partial objects, and saving those wiped untouched fields.
- Ticket numbers come only from the `next_ticket_number()` database function via `src/lib/tickets.ts` (daily Nairobi counter, prefix in `system_settings.ticket_prefix`; uniqueness is per `tickets.queue_date`) — the first ticket of a day also closes previous-day triage.
- Instant updates use one app-wide realtime channel (`src/lib/liveUpdates.ts`, mounted by `LiveUpdatesHub`); screens listen with `useLiveTable` instead of opening their own channels; the `live_updates` setting switches to 60-second refresh.
- Form autosave uses `useFormDraft` + `DraftStatus` (per-user browser drafts, 24 h expiry, wiped on sign-out because machines are shared); inventory edits save only changed fields so concurrent stock movements are not overwritten.
- "Log in as" tabs are isolated by `src/lib/isolatedSession.ts` (first import in `main.tsx`: per-tab storage + private sign-in broadcast channel), opened via `/login-as#t=<one-time token>` from the `admin-login-as` function; sign-outs go through `signOutThisTab` — so the admin tab keeps its own session and closing the impersonated tab never ends the real user's other sessions.
- Ticket/OPD counters are read-only to app users; only the numbering database functions write them.
- Lab result templates (answer lists, age/sex reference ranges, critical thresholds, flags, reporting categories) live only in `src/lib/labFields.ts` with bun tests beside it (`bun test ./src/lib/labFields.test.ts`) — entry, saved flags, critical alerts and lab reports all read them. Finished results display the saved lines, not today's template.
- Pharmacy stock changes go through database functions: `pharmacy_receive_stock` (delivery, no approval) and `pharmacy_set_stock` (stock-count change from Edit) — each updates the balance in one step and writes the stock-card line, so cards and balances never disagree. Stock status / expiry / value rules for reports live in `src/lib/pharmacyReport.ts` with bun tests beside it (`bun test ./src/lib/pharmacyReport.test.ts`); exports in `pharmacyExport.ts`.
- Billing-desk reports (Billing → Reports: payments, bills & balances, services charged) are open to reception and finance. Bill / charge filtering and grouping live in `src/lib/billsQuery.ts` with bun tests beside it (`bun test ./src/lib/billsQuery.test.ts`); table-shaped exports share `src/lib/tableExport.ts` (CSV, Excel with SUM/SUMIF formulas, letterhead PDF).
- Self-editing of personal details is blocked by the `block_self_personal_edit` trigger on `profiles` and `patients` (only bookkeeping columns such as `must_change_password` / `last_login_at` may change on one's own row; admins exempt) — screens show details read-only, but the database is the guarantee.
- "Clear cache for everyone" bumps `system_settings.cache_version`; `useCacheReset` (mounted by `LiveUpdatesHub`) compares it with the browser's stored copy on load / tab focus / every minute and wipes localStorage (except sign-in tokens), the query cache and Cache Storage, then reloads — so a super admin can reset every browser without signing anyone out.
- Bills are built by `createInvoiceForTicket(ticketId, confirmed)`: Billing passes exactly the lines and amounts on screen at Confirm, new lines join the visit's untouched unpaid bill instead of opening a second one, and every bill line is written to `invoice_items` — receipts list those lines, so the receipt shows what was confirmed. Fee waivers by patient type live in `serviceFee` in `src/lib/pricing.ts`.
